# 用 requestAnimationFrame 实现浏览器动画

## Goal

真正弄明白如何用 `requestAnimationFrame()`（浏览器在下一次绘制前调用回调的动画调度接口）实现一个平滑、可控、速度不依赖屏幕刷新率的动画。

完成这次研究后，我应该能从零写出一个方块移动动画，并能解释每一帧为什么要这样计算、何时继续、何时停止，以及卡顿时该先检查什么。

## Questions

- [ ] Q1：浏览器动画的一帧里，我负责更新什么，浏览器负责绘制什么？`requestAnimationFrame()`（浏览器动画帧调度接口）到底帮我安排了哪个时机？
- [ ] Q2：一次 `requestAnimationFrame()`（请求下一次绘制前回调的接口）调用为什么只执行一次？如何让 `animate()`（每帧更新动画状态的函数）形成可停止的循环？
- [ ] Q3：`timestamp`（浏览器传入动画回调的时间戳）、`elapsed`（从动画开始到当前帧经过的总时间）和 `deltaTime`（当前帧与上一帧之间经过的时间）分别应该在什么场景使用？
- [ ] Q4：为什么“每帧移动 2px（像素）”会出问题？如何实现“无论 60Hz（每秒刷新 60 次）还是 120Hz（每秒刷新 120 次），都在一秒内移动 200px（像素）”？
- [ ] Q5：开始、暂停、继续、重置和自然结束时，动画循环分别应该处于什么状态？如何避免重复点击后产生多个并行循环？
- [ ] Q6：页面切到后台、主线程被 Long Task（长时间占用主线程的任务）阻塞、或两帧间隔突然变大时，动画为什么会异常？该如何观察和处理？
- [ ] Q7：`requestAnimationFrame()`（浏览器动画帧调度接口）只能解决调度时机吗？`transform`（只改变元素视觉变换的 CSS 属性）、`left`（影响元素布局位置的 CSS 属性）和 CSS Animation（由浏览器样式系统执行的声明式动画）分别如何选择？

### Q1：一帧动画中谁做什么？

查到：

- [ ] 先写一个没有动画库的页面：一个方块、一个开始按钮和一个用于显示当前数值的文本。
- [ ] 用自己的话画出“JavaScript（网页脚本语言）更新状态 -> 浏览器绘制页面 -> 用户看到新位置”的过程。
- [ ] 查阅 `requestAnimationFrame()`（浏览器动画帧调度接口）的回调时机，并记录它与浏览器绘制的关系。
- [ ] 在回调里打印一次 `timestamp`（动画回调时间戳），确认回调确实获得了时间信息。

### Q2：动画循环如何开始和继续？

查到：

- [ ] 只调用一次 `requestAnimationFrame()`（请求下一次绘制前回调的接口），观察方块是否只更新一次。
- [ ] 在 `animate()`（每帧更新动画状态的函数）末尾再次调用 `requestAnimationFrame()`（请求下一次绘制前回调的接口），观察连续动画如何出现。
- [ ] 故意把“再次请求下一帧”放到条件分支外和分支内，对比动画结束后是否仍持续运行。
- [ ] 写下 `requestId`（已登记动画回调的标识）需要保存在哪里，以及它在什么时刻会变化。

**Conclusion**

> 待研究。

### Q3：时间应如何进入动画计算？

查到：

- [ ] 记录第一帧的 `timestamp`（动画回调时间戳），决定如何初始化 `startTime`（动画开始时间）和 `lastTime`（上一帧时间）。
- [ ] 用 `elapsed`（动画已运行的总时间）实现“在一秒内从 0 移动到 200px（像素）”。
- [ ] 用 `deltaTime`（相邻帧时间差）实现“以每秒 200px（像素）的速度持续移动”。
- [ ] 对比两种公式分别适用于“固定时长动画”和“持续运动”的原因。
- [ ] 记录第一帧、暂停后恢复、重置后三种情况下时间变量应如何处理。

**Conclusion**

> 待研究。

### Q4：刷新率为什么会影响按帧计算？

查到：

- [ ] 做一个“每帧移动 2px（像素）”的版本，记录在相同真实时间内的总位移。
- [ ] 做一个基于 `deltaTime`（相邻帧时间差）的版本，记录在相同真实时间内的总位移。
- [ ] 若设备可用，分别在 60Hz（每秒刷新 60 次）与 120Hz（每秒刷新 120 次）环境运行；否则人为模拟不同帧间隔。
- [ ] 用表格比较“回调次数、运行时间、总位移、视觉速度”。

**Conclusion**

> 待研究。

### Q5：如何管理动画生命周期？

查到：

- [ ] 给页面加入“开始”“暂停”“继续”“重置”按钮。
- [ ] 定义 `isRunning`（动画是否正在运行的状态）和 `requestId`（已登记动画回调的标识）各自负责什么。
- [ ] 用 `cancelAnimationFrame()`（取消尚未执行动画回调的接口）实现暂停，并验证暂停后方块不会继续移动。
- [ ] 连续快速点击“开始”，确认同一时间只有一个 `animate()`（每帧更新动画状态的函数）循环。
- [ ] 为“到达终点”设计停止条件，并记录为什么自然结束时不应再请求下一帧。

**Conclusion**

> 待研究。

### Q6：掉帧、后台与大时间差如何处理？

查到：

- [ ] 切换到后台标签页再回来，观察 `deltaTime`（相邻帧时间差）是否突然变大。
- [ ] 人为加入 Long Task（长时间占用主线程的任务），观察方块位置、帧间隔和页面响应。
- [ ] 思考：若一次 `deltaTime`（相邻帧时间差）很大，物体应直接跳到新位置，还是需要限制最大时间差？分别适合什么场景？
- [ ] 使用浏览器性能面板记录一次掉帧，并写下阻塞发生在哪里。

**Conclusion**

> 待研究。

### Q7：调度正确后，怎样避免渲染仍然卡顿？

查到：

- [ ] 用 `transform`（只改变元素视觉变换的 CSS 属性）移动方块，再用 `left`（影响元素布局位置的 CSS 属性）移动方块。
- [ ] 观察 Reflow（浏览器重新计算页面布局）和 Repaint（浏览器重新绘制像素）对两种写法的影响。
- [ ] 尝试在每帧交替读取布局信息和写入样式，观察 Layout Thrashing（反复强制布局计算导致的性能抖动）。
- [ ] 选一个简单效果，分别用 `requestAnimationFrame()`（浏览器动画帧调度接口）和 CSS Animation（由浏览器样式系统执行的声明式动画）实现，比较可控性与代码量。

**Conclusion**

> 待研究。
